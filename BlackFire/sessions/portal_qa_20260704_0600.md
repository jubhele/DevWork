## JavaScript & CSS  [PASS — with minor FLAGS]

### innerHTML Safety

All 112 `innerHTML` assignments in `portal.js` were audited against user-supplied data. All data from API responses that reaches `innerHTML` passes through the local `esc()` helper (which HTML-encodes `&`, `<`, `>`, `"`). Examples confirmed clean:

- `portal.js:667` — client dropdown: `esc(label)` applied before injection.
- `portal.js:684` — tech dropdown: `esc(u.username)`, `esc(u.name)`, `esc(lbl)` used.
- `portal.js:697–716` — callout/quote dropdowns: all fields wrapped with `esc()`.
- `portal.js:3430` — tracker updates panel: `esc(row.created_by)`, `esc(row.label)`, `esc(row.content)` applied; `row.id` used only in element-ID attributes (DB integer, safe).
- `portal.js:4118`, `5188` — error message injection: `esc(r.error)` applied.

**FLAG (low risk)** — `portal.js:7024` — `s.label` inserted into `<option>` text content inside `secOpts` template without `esc()`. `s.label` is drawn from the hardcoded `SAFETY_SECTIONS` constant (not user data). No immediate XSS risk, but defensive coding would apply `esc()`. Recommend fixing next sprint.

**FLAG (low risk)** — `portal.js:7322` — `sec.label` concatenated bare into `innerHTML` inside `_buildTrackerHTML`. Again drawn from hardcoded SECTIONS constant. No user data path. Same recommendation: wrap with the local `esc()` defined at line 7021.

**FLAG (low risk)** — `portal.js:7210, 7223–7226` — Downloadable tracker HTML template includes inline `onclick` handlers (`submitFile()`, `toggleGuide()`, `resetAll()`, `window.print()`). This template is emitted as a standalone downloadable file with no portal CSP, so the main app's nonce enforcement does not apply. Handlers reference only hardcoded function names — no user data involved. Violates the spirit of the no-inline-handler rule; recommend converting to `addEventListener` bindings inside the generated `<script>` block.
