# Portal QA Report — 2026-07-10 06:00 SAST

## PHP Safety  [ISSUES FOUND]

**FLAG — `api/transactions.php` line 31: missing `like_escape()` in LIKE search**

The search handler builds its LIKE pattern without escaping user input for wildcard characters:

```php
$like = "%$q%";   // ← $q is not passed through like_escape()
```

This means a user who searches for `100%` or `test_foo` can trigger unintended SQL wildcard matches (every row vs. only rows containing a literal `%`/`_`). There is **no SQL injection risk** — prepared statements are used correctly — but the behaviour diverges from the `invoices.php` endpoint which correctly calls `like_escape()`:

```php
// invoices.php (correct)
$like = '%' . like_escape($q) . '%';
```

**Fix:** replace line 31 of `api/transactions.php` with:
```php
$like = '%' . like_escape($q) . '%';
```
