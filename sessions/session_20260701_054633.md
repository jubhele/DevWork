## Learnings
- The v2 plan's "Drizzle schema ALREADY COMPLETE" claim was based on table-name presence, not column parity. Live has 39 non-backup tables; Drizzle has 31 + 20 phantom columns. Always column-diff before scoping a "schema is done" phase.
- Drizzle `.primaryKey().autoincrement()` implies NOT NULL — no `.notNull()` needed. Future parsers/audits must treat PK as NOT NULL to avoid noisy false positives.
- Enum-case mismatch (live=lowercase vs Drizzle=TitleCase) is a workspace-wide pattern, not a per-table bug — fix in one sweep across PHP constants, apps/web enums, and umlilo TS unions.
- The `bf_safety_*` family was refactored in live to FK ID columns (`*_id`) while Drizzle still uses denormalised string columns — the safety domain needs a structural rebuild, not patches.
- `drizzle-kit introspect:mysql` should be the canonical schema regen path going forward; hand-authored Drizzle schemas drift silently from live DDL.
- Regex-parsing TS is fragile once column definitions include nested option objects (`{ length: N }`, `{ precision, scale }`, `{ unsigned: true }`). Use a brace-depth extractor per table body instead of non-greedy `.*?`.
