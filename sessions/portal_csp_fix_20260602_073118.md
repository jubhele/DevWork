## Decisions
- Used nonce-tagged `<style>` injection (not `unsafe-inline`) — PHP already generates a nonce for script-src; reused it for style-src
- Exposed nonce to JS via `<meta name="csp-nonce">` — avoids a separate API call
- Dynamic chart bar heights and progress fill widths → `_injectStyle(id, css)` helper with data-pfi/data-cbi index attributes
- All `element.style.display = x` → `$show(el, d)` / `$hide(el)` using CSS utility classes (.d-none, .d-flex, etc.) with !important overrides
- subBar.visibility → `.invis` CSS class toggle
- Message feedback states (forgot/reset password) → .msg--ok / .msg--err CSS classes
- Transaction net color → .net--pos / .net--neg CSS classes
- Navigation top offset → `_injectStyle('nav-top-css', ...)` 
- HTML template inline style attributes → replaced with semantic CSS classes in portal.css
- Tracker blob (lines 5457-5870) and report blob (5923-6034) are standalone HTML downloaded as Blobs — NOT subject to portal CSP; left untouched
- Statement download blob (lines 3097-3119) also left untouched for same reason

## Learnings
- Chrome blocks JS `element.style.property = value` under strict style-src CSP (same as HTML inline styles)
- Hashes in CSP `style-src` don't work for dynamically-computed values — they're only useful for static inline style strings
- `element.hidden = true/false` does NOT trigger CSP violations (it's an HTML attribute, not an inline style) — viable alternative for simple show/hide
- The `_injectStyle` pattern (replace a `<style nonce="...">` element's textContent) is the correct CSP-safe way to apply computed CSS values from JavaScript
- portal.js contains embedded standalone HTML blob templates (tracker, report, statement) that are NOT part of the portal DOM — these are exempt from the portal's CSP and should not be modified for this purpose
