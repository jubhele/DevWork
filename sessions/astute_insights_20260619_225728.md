## Decisions
- Wired login and dashboard to real Next.js App Router API stubs rather than touching build tooling.
- Auth uses an HttpOnly cookie (`astute_session`) carrying a base64-encoded JSON token — no external auth library.

## Resumed 2026-06-20 (pass 3)

## Decisions
- Built a proper mobile navigation stack with zero new dependencies — `react-native-safe-area-context` and `react-native-screens` were already in package.json as peer deps.
- Used a custom NavContext (tab state + brief stack) so the screen files are structurally identical to what they'd be under React Navigation — easy to swap later.
- Split the monolithic App.tsx into 8 files: data, navigation, and 4 separate screens.
- Stack push/pop is scoped to the Briefs tab; tapping a tab always resets that tab's stack to its root.
- BriefDetailScreen receives its data as a prop from the navigator (no global store needed at this scale).

## Work Done
- Created `apps/mobile/src/data.ts` — 4 briefs, 3 alerts, 3 metrics (all using `astuteinsights.co.za` domain flavour).
- Created `apps/mobile/src/navigation.tsx` — NavContext, AppNavigator (SafeAreaProvider + Navigator + TabBar), useNav hook.
- Created `apps/mobile/src/screens/HomeScreen.tsx` — greeting, 3-metric grid, weekly summary card.
- Created `apps/mobile/src/screens/BriefListScreen.tsx` — scrollable brief list with tag chips and date; each item pushes to detail.
- Created `apps/mobile/src/screens/BriefDetailScreen.tsx` — back button, tag, large display-font title, body copy.
- Created `apps/mobile/src/screens/AlertsScreen.tsx` — read/unread indicator (aurum dot + border tint), unread count badge.
- Replaced `apps/mobile/App.tsx` with a 6-line shell that mounts AppNavigator.

## Blockers / Next Steps

- Replace in-memory stub data with real API calls (mirror the web `/api/dashboard` pattern).

## Learnings
- Custom NavContext with a stack array is the lightest path to real push/pop navigation in Expo — it reads exactly like React Navigation from the screen's perspective.
- Keeping stub data in a single `data.ts` file makes it trivially replaceable with a fetch call later.
