## Learnings (addendum)
- `.gitignore` does not hide a path already tracked in the index — including gitlinks (mode 160000) left over from a removed/never-configured submodule. `git rm --cached` is required regardless of ignore rules. When auditing for "project X still tracked in root repo," check both `git ls-files | grep` (full tree) and `git ls-files -s | grep 160000` (gitlinks) — they're different failure modes needing the same fix.
- `git commit -- <pathspec>` on a path that's simultaneously covered by a *new* `.gitignore` rule can silently drop that path from the commit even though it was staged. Verify with `git ls-files -s <path>` (or `git show --stat`) after any commit involving a just-ignored path, rather than trusting the commit output alone.
